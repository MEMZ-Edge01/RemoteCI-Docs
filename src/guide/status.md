# 开发状态

RemoteCI 当前版本为早期开发快照，不是已经完成三端验收的稳定版本。

## 已从源码确认

- 项目包含 ClassIsland 插件、ASP.NET Core 服务端、Wear OS 客户端和共享协议。
- 服务端使用 SQLite 保存账号、权限、会话和插件凭据。
- 插件设计了局域网 WebSocket 与云端中转两种连接。
- 服务端包含健康检查、状态、课表、用户和命令相关接口。
- Dockerfile 可以从仓库根目录构建服务端镜像。

## 当前明确不一致

| 范围 | 当前情况 | 影响 |
| --- | --- | --- |
| 插件云端配对 | 服务端公开 <code>/api/plugin/pair</code>，插件仍请求旧的 <code>/api/pair</code> | 云端插件配对会失败 |
| 手表登录 | 服务端返回 <code>accessToken</code> 等新字段，手表仍读取旧的 <code>token</code> 字段 | 云端登录响应无法正确解析 |
| 远程命令 | C# 与 Wear OS 的命令编号和载荷结构不同 | 换课和通知命令不能视为兼容 |
| 课表模型 | C# 已把课程列表拆入独立课表模型，手表仍从旧快照字段读取 | 课程选择数据可能缺失 |
| 手表连接调用 | 连接函数已要求密码，部分界面调用仍未传入 | Wear OS 当前源码可能无法构建 |
| 管理页面 | 静态页面使用的登录字段和通知接口与服务端不一致 | 管理页面不能视为成品 |

## 验证边界

为遵守“不要动 RemoteCI 文件夹”的要求，本次只读检查了源码，没有在 RemoteCI 中执行构建、测试或运行服务。因为这些操作会产生 <code>bin</code>、<code>obj</code> 或其他构建文件。

因此当前只能确认文档站本身可以构建，不能确认：

- 服务端镜像能够从当前未提交工作区成功构建。
- 插件包能够生成并被 ClassIsland 加载。
- Wear OS APK 能够构建和安装。
- 局域网、云端、通知与课表操作可以端到端完成。

## 何时可以移除警告

至少完成以下验证后，才能把快速开始改为稳定教程：

1. 服务端、插件和 Wear OS 客户端在同一提交上构建成功。
2. 插件完成一次性配对并保持云端 WebSocket 连接。
3. 手表账号登录、令牌续期和会话撤销均通过。
4. 当前状态与七日课表成功同步。
5. 交换、替换课程和发送通知按权限返回正确结果。
6. 局域网优先与云端回退在真机上通过。
7. Docker、HTTPS、备份和恢复流程完成实际演练。
